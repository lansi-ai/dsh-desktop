核心结论

你不需要从零写程序

  • UI：官方 Slots 槽位系统允许在侧边栏/对话流/设置页任意位置注入业务组件，也可以整屏替换（最后手段）。
  • 功能：视频生成对底座而言只是「一个新工具（tool）+ 一个新 provider（video 域，类比 llm 域）」，Agent 循环/审批/沙箱/持久化全部白拿。
  • 工作流：上游已有 dsh-tool-workflow（JS 编排引擎）+ dsh-client-ui-workflow-run（工作流节点 UI）+ dsh-jobs（后台任务）+ ui-deliverables（产物展示）——视频工作流的骨架四件套现成。
  • 分发：electron-builder 打包链已通（M4-a1），垂直版 = 换 productName/appId + 裁剪清单。
阶段 A · 纯注入→ 阶段 B · 业务域插件→ 阶段 C · 裁剪通用面→ 阶段 D · 独立分发 （每阶段可独立交付）

四层扩展面（自上而下）

🖥 UI 层：Slots 槽位注入 最轻 · 先从这里开始

  • 位置：src/desktop-shell/web/<your-plugin>-client.js（浏览器 bundle）
  • 注册：boot-graph.ts 的 desktopDecls 数组追加条目（现有 5 个 @dsh-desktop 条目即模板）
  • 查槽位：各 ui-* 包的 lib/types/client/contract/slots.d.ts 声明了暴露的槽位契约
// 视频工作室设置页注入示例（照抄 desktop-settings-client.js 结构）
window.__ModuleLoader__.load({
  id: '@yourbiz/video-studio',
  factory: (require) => {
    const React = require('react'); const h = React.createElement
    exports.inject = ['slots']
    exports.apply = (ctx) => {
      ctx.slots.inject('settings.section', () => ctx.slots.register({
        name: 'settings.section', id: 'video-studio', order: 20,
        label: () => '视频工作室',
      }, function VideoStudioSection() { /* 业务组件 */ }))
    }
  },
})
槽位现状视频案例用法
settings.section✅ 已验证（desktop-settings 在用）「视频供应商 / API Key / 默认分辨率」设置页
sidebar.footer.action✅ 已验证（desktop-panel 在用）「新建视频任务」入口按钮
settings.general.item⚠️ 被官方占用（坑 13：勿重复声明）—
conversation / hero 等契约见各 ui-* 包 slots.d.ts对话流内嵌「视频预览卡」
⚠️ 极限操作（整屏替换，隐藏侧边栏/对话流）：不要改官方 dist（红线：发行物只读）；用 CSS 注入或 fork dsh-web-frontend 自建 dist（ADR-006 自绘 UI 路线）——成本高，放阶段 C 之后。

⚙ Host 功能层：注册业务工具与 provider 自然语言驱动的关键

  • 路径一 · 桥方法（按钮型）：bridge unary 方法 + preload 命名空间 —— 照抄 desktop-audit-viewer.ts 模板，适合「点按钮调 API」
  • 路径二 · Agent 工具（模型可调用）：向 ctx.tools 注册 video_generate 工具 —— 最大红利：模型在用户说「帮我把这段脚本做成 30 秒视频」时自动调用；中途追问走 user-questions，高消耗走 approval，交互链全白拿
  • 路径三 · provider 域（多供应商）：定义 ctx.video 服务，结构照抄 dsh-llm + dsh-llm-deepseek 的注册面；MVP 先跳过，路径二写死单供应商
// 路径二：video_generate 工具（MVP 形态，先项目内模块）
// 工具定义：name / description / parameters(zod)
// handler：校验参数 → 提交渲染任务（走 dsh-jobs 后台任务）→ 返回任务句柄
// 装配：boot.ts prepare 或 main.ts bootstrap 接入

💾 数据层：配置与存储 全部有现成机制

  • 用户偏好（供应商/分辨率）：ctx.settings.register('video-studio', schema) —— 照抄 desktop-api.ts 的 lazySettingsScope
  • 业务对象（项目/任务清单）：ctx.storageDomain（JSON 后端已在装）或桥方法读写 userData
  • 任务状态：复用 dsh-jobs（session/jobs 帧已通 UI）—— 勿自造

🖥 ⚙ 系统层：桌面集成 M2/M3 已建成

  • 渲染完成通知：desktop-notify.ts 消费 events.mux 流——业务 job 事件走官方 jobs 通道，通知自动生效
  • 任务面板独立窗口：WindowManager 会话窗口机制可加 windowKind 分支绑定业务窗口
  • dsh:// 协议：dsh-protocol.ts 加 action（如 dsh://newvideo?template=x）供外部系统唤起建单

案例路线：AI 视频创建工作流

阶段 A · MVP：纯注入不动底座内核目标：跑通 上传素材 → 对话生成脚本 → 提交渲染 → 收到成品
  1. A1 业务设置页（settings.section 槽）：视频供应商 API Key（环境变量注入，禁止硬编码）、默认参数
  2. A2 侧边栏入口（sidebar.footer.action）：「视频工作室」面板（desktop-panel-client.js 直接抄壳）
  3. A3 video_generate 工具（路径二）：单供应商写死；内部用 dsh-jobs 起后台任务，轮询供应商 API
  4. A4 产物交付：渲染产物落工作区目录 → ui-deliverables 自动展示成品引用；通知走 jobs 事件白拿
✅ 验收：一句话「把 input/script.md 做成 720p 视频」→ 审批 → 后台渲染 → 托盘通知 → 对话流里点开成品
阶段 B · 垂直化：业务域一等公民扩展深水区
  1. B1 工作流编排：多步流水线（脚本→分镜→TTS→合成）写为 dsh-tool-workflow 编排脚本；可沉淀为 skill（resources/skills/video-pipeline/）
  2. B2 专用 UI：对话流内嵌视频预览卡（conversation 槽位）+ 任务列表 Tab（抄 desktop-audit-viewer 双件套模式）
  3. B3 多供应商（路径三）：ctx.video 域 + provider 插件矩阵
  4. B4 斜杠命令：/newvideo、/render —— 往 dsh-commands 注册表添加 command 插件（照抄 dsh-command-goal 形态）
阶段 C · 裁剪通用面做减法
  1. C1 隐藏不相关 UI：boot-graph CLIENT_EXCLUDE_IDS 追加要藏的官方插件（现成机制）—— 如 ui-trajectory、ui-settings-plugins
  2. C2 persona 定制：boot.ts §2 system-prompt persona 覆写为视频导演角色（一行改动）
  3. C3 agent-presets：resources/agent-presets/ 加 videographer 预设（绑定工具子集+提示词），开箱即用
  4. C4 默认视图：确需「非对话式」主界面（如看板型）才启用 ADR-006 自绘 UI —— 代价大，仅在注入方案确证不满足后启动
阶段 D · 独立分发成品化
  1. D1 品牌分离：复制工程 → 改 package.json name/version、electron-builder.yml 的 appId/productName/icon
  2. D2 裁剪依赖：不需要的域从 boot.ts §1 insert 删除，减小体积
  3. D3 更新通道：复用 M4-b 更新描述符机制（规划态，先手动发包）
  4. D4 上游同步：底座升级时走 docs/upstream-migrations.md 的 sync-upstream SOP

避坑清单（垂直化高频雷区）

#坑出处 / 对策
假 slot：向不存在的槽位注册是静默 no-op，无报错坑 13：先用 slots.d.ts 核对槽位契约
client bundle 里 exports.inject 写服务名会 PENDING（服务等待）坑 15：inject: []，服务用 ctx.get 软查找
非 insert 补丁对空根配置是静默 no-op坑 16：Host 插件必经 boot.ts insert 数组
React in bundle：用 createElement 不用 jsx-runtime；children 放 propsdesktop-settings-client.js 头注
通道常量 preload 内联与 types/channels.ts 人工同步preload.ts 头注
图标 / 资源随 nativeTheme 黑白双版desktop-tray.ts
供应商 API Key 走环境变量，禁硬编码core-standards 红线
大文件产物走 spill-local，勿塞会话上下文boot.ts spill 配置
