# 13 · UI 设计愿景 — Desktop-First 自绘界面（与原 Web UI 的差异化）

> 状态：**暂缓（二期可选）** — 本期主线为「官方 UI 复用 + 内嵌宿主」（L2），自绘 UI 不纳入本轮交付。
> 触发：用户明确「现有 Web UI 太难用，希望桌面产品样式不同」——待 L2 骨架打通后，可按此文档切 renderer 为自绘面。
> 配套决策：[ADR-006](adr/adr-006-custom-ui.md)（暂缓·可选）；[ADR-007](adr/adr-007-plugin-compat.md)（零端口兼容，本期主线）。

## 1. 为什么「官方 Web UI 的布局不适合桌面」

官方 Web UI（`apps/web` + `ui-layout/sidebar/conversation/trajectory`）本质是**浏览器页面**布局：
- 固定三栏（窄侧栏 + 会话列 + 消息区）+ tab 环（对话/轨迹）切换——桌面用户习惯的是**单文档区 + 可折叠面板 + 快捷键穿梭**；
- 管理功能（设置/技能/插件）埋在页面深层，没有桌面应用的「设置窗口/命令面板」心智；
- 依赖浏览器窗口（URL、刷新、返回），桌面场景的焦点/驻留/多窗口直觉（tray、全局热键、drag&drop）缺失；
- 信息密度取舍保守（大留白、多级 tab），对重度用户（同时多会话、后台任务、工具调用审计）效率低。

## 2. 设计目标（差异点清单，全部可验收）

| # | 原则 | 官方 Web UI（现状） | Desktop UI（目标） |
| --- | --- | --- | --- |
| D1 | 键盘优先 | 鼠标点击为主，少量 `/` 命令 | **全局命令面板（Ctrl+K）+ 全键盘导航**（方向键/j-k 切换会话与消息）；任何操作 ≤2 键可达 |
| D2 | 单义主区 | 侧栏+会话列+消息区三栏并存 | **主窗口默认单栏对话流**；会话列表为可折叠抽屉（<快捷键唤出），专注写作/阅读 |
| D3 | 轨迹内联 | 轨迹是独立 tab 页 | 工具调用/中间产物折叠成**时间线内联**（一次点击展开），不再翻页 |
| D4 | 状态可见 | 无全局活动指示 | 窗口标题/托盘图标/侧栏顶部常驻「agent 状态」（运行中·等待审批·后台任务 N）实时投影 |
| D5 | 原生交互 | 无 | 托盘、全局热键（Spotlight 输入）、系统通知、拖放附件、右键「发送给 agent」、`dsh://` 唤起 |
| D6 | 视觉语言 | `--dsw-alias-*` 通用 token | **自有设计 token**（字体/密度/圆角/配色），支持 Light/Dark/自定义主题，可整体替换 |
| D7 | 信息密度 | 宽松 | **密度可调**（紧凑/舒适两档）；长会话自动分组（按目标/任务分段），可折叠 |
| D8 | 多窗口 | 无 | 会话可弹出为独立窗口（对照/多任务）；会话窗口带独立状态栏 |

## 3. 信息架构（初版）

```
主窗口
├─ 顶栏        会话标题 · agent 状态芯片 · 模型/预算快速切换 · 按钮（抽屉/命令面板/设置）
├─ 主区
│  ├─ 对话流    消息气泡（用户/助手）内联时间线（工具调用、轨迹节点、产出文件、工作流）
│  ├─ 输入坞    composer（多行 + 附件拖放 + @引用 + /命令）+ 计划模式开关 + 目标条
│  └─ 抽屉(可折叠) 会话列表(最近/任务分组) · 后台任务 · 插件状态
├─ 命令面板(Ctrl+K)  动作=切换会话/运行命令/打开设置/开关插件/发送文本（Spotlight 输入复用）
└─ 设置窗口(原生)    通用·模型·插件·桌面能力（通知/热键/自启/剪贴板/更新）·存储数据
独立窗口
├─ 会话窗口(可多个)  复用对话流视图 + 状态栏（会话/运行/审批）
└─ 兼容窗口(老插件)  官方 Web UI 容器（见 ADR-007）
```

## 4. 桌面特有交互规格（P0）

| 交互 | 规格 | 对应需求 |
| --- | --- | --- |
| 全局快速输入 | `Ctrl+Shift+Space` 无边框小窗：输入→回车→会话收件（复用 composer 语义） | R-07 |
| 命令面板 | `Ctrl+K`：模糊搜索动作；`> 模式`执行命令；`/ 模式`查插件命令 | R-16 |
| 会话弹出 | 会话菜单「在独立窗口打开」/ 拖拽会话到窗口外 | R-09 |
| 选择即发送 | 任意窗口选中文本 → 右键「发送给 agent」（带来源上下文） | P2 |
| 拖放附件 | 文件/文件夹拖入输入坞 → 附件或工作区路径（经 `attachment` 服务） | R-14 |
| 审批浮层 | 需要审批时：通知 + 窗口聚焦 + **原生确认浮层**（显示待批动作细节，Approve/Deny） | — |
| 完成收束 | agent 完成：通知 + 标题回静 +（可选）声音；失败：红色状态 + 「查看轨迹」直达 | — |

## 5. 视觉语言草案

- **基调**：桌面工具、克制、信息优先；默认深色（低光编码环境），浅色随主题
- **排版**：等宽为主（Cascadia Code / JetBrains Mono），正文 13.5–14px，行高 1.55，密度两档
- **颜色**：自建语义 token（bg/layer/border/label/accent/success/warn/error/approval），不依赖 `--dsw-alias-*`
  （兼容窗口内仍用官方 token——两个 token 体系并存、互不干扰）
- **动效**：微动效（面板滑入、状态芯片脉冲、审批浮层）；尊重 `prefers-reduced-motion`
- **主题化**：CSS 变量集中定义 → 插件/用户可整体换肤（与官方 skin 概念对齐但走我们的 token 面）

## 6. 渐进式自绘策略（控制成本的关键决策）

**不一次性重写所有管理面**，分三波（对应 roadmap M1/M2/M5）：

| 波次 | 自绘范围 | 官方 UI 仍承载 |
| --- | --- | --- |
| M1 | 启动/装载页、对话流（消息+时间线+输入坞）、会话列表抽屉、命令面板骨架 | 暂无（M1 是自绘壳 + host 打通，可先只做对话流最小集） |
| M2 | 状态投影、设置窗口（通用/模型/桌面能力）、审批浮层、托盘/通知交互面 | 技能(skills)、插件管理(plugin-inventory)、高级会话设置——**兼容窗口承载** |
| M5 | 插件管理面渐进迁移、主题化、密度调节 | 逐步清空兼容面，仅「老 web client 插件」保留兼容窗口 |

> 兼容窗口不是「套壳」：它是**可选、默认关闭、仅承载浏览器面向旧插件**的次级容器；主应用的全部日常路径都在自绘 UI。
> （对「套壳」判定的边界见 [README 判定表](../README.md)。）

## 7. 与现有插件兼容的 UI 侧结论（引出 ADR-007）

- 你的三个插件（`dsh-terminal` / `dsh-rule-manager` / `dsh-restart`）的浏览器半依赖官方槽位
  （`conversation.view` / `settings.section` / `sidebar.footer.action`）与同源 fetch：
  - **M2 起**：兼容窗口默认打开旧插件所需槽位（官方 UI 全量），老插件在窗口内**无改动可用**；
  - **长期**：向新 UI 迁移的插件，可改挂我们自绘 UI 的对等面（新槽位）或由 slot shim 承接（视觉混在，逐步替换）。
- 详情与三案对比见 [ADR-007](adr/adr-007-plugin-compat.md) 与 [`06-client-plugins.md`](06-client-plugins.md)。
