# ADR-005 · 上游版本钉死与升级机制

状态：**已接受**（2026-08）· 关联：[`09-roadmap.md`](../09-roadmap.md) 持续任务、[`11-risks.md`](../11-risks.md) R1/R19

## 背景
官方 developer preview、破坏性变更被书面承诺；本机 npm 基线 rc.7 与 GitHub Latest rc.12 存在偏差且频道独立发布。

## 决策
1. **锁基线**：`_harness-src` 以 git 子模块钉 commit/tag；`dsh--version` 基线常量进 CI 门禁；
2. **耦合收敛**：与上游耦合只允许在 3 类文件（装配模块、IPC 载波、bundle patch）内，其他代码不得依赖上游内部形态；
3. **升级节奏**：每个 rc 发布执行 `sync-upstream.sh <tag>`：拉取→diff 三类耦合面→迁移登记→全量回归→发布 rc 构建；
4. **迁移登记表**（本 ADR 附）：记录每次升级的 breaking 变更、影响面、迁移动作；
5. 回滚策略：桌面应用层版本与上游基线解耦（应用二进制可独立回滚），数据格式兼容优先（JSONL append-only）。

## 理由
- 上游明确「未来将出现破坏兼容性的变更」，不钉版本 = 持续修 bug；
- 社区桌面与官方 npm next/Release 双频道并存的混乱（README 明确提示）是反面教材——我们只认一个基线源。

## 后果
- 升级成本显式化（每次 rc 一次同步任务）；但换来自营可控与可回滚；
- 注册表与 R1/R19/R20 联动：typert 迁移等大改在登记表预判。

## 备选否决
- 跟随 npm next 最新：收益不确定、风险即时兑现
- 完全不跟随：焊死版本，错过安全/功能修复

## 复查触发
每个 rc；官方宣布稳定版（rc → stable）时重估一次。
