关键数据流

⬆ 上行 RPC（unary）
  1. 官方 UI / 插件调用 → ipc-connection.doFetch
  2. desktopBridge.request（信封透传，保留 rpcId）
  3. ipcMain.handle('dsh:rpc') → zod 校验
  4. bridge 查 unary methodTable（桌面方法优先）
  5. 未命中 → apiProxy toFetchHandler 虚拟路由 /api/<method>
  6. 404 → typertGateway.invokeRpc 兜底（坑 12）
  7. 解包 server-response → {rpcId, data|error} 回 renderer
⬇ 下行帧（server-request）
  1. Host 事件 → apiProxy.events.mux / host 流
  2. carrier-relay 逐帧 pump（per-window）
  3. webContents.send('dsh:frame', payload)
  4. preload onFrame → 入队 + waiter 唤醒
  5. readIpFrames 重包 {rpcId, payload} AsyncIterable
  6. 官方 ConnectionController 分发到各 sink
  7. 应答：respond(rpcId, body) → /api/respond 回填
🧩 插件装配双通道
  1. Host 半：空根 cordis.yml + overlay patches（§1 insert 约 70 条服务插件）
  2. prepare 钩子注入：cmdline / desktopStartup / ElectronDirectoryPicker / ctx.desktop / webServer compat
  3. Client 半：boot-graph 扫描 dsh.client 声明 → __DSH_BOOT__ 图谱注入 HTML
  4. 图谱条目 = 官方驱动全量激活；client-connection 仅预载注册（D-9）
  5. 桌面 UI 插件经官方 Slots 槽位共存注入
  6. 第三方插件：host 半靠 webServer 等价面无改动激活，client 半靠 bundle 直读
