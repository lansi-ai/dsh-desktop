# 02 · 需求与产品定位

## 1. 产品定位

**dsh-desktop**：面向个人的 DeepSeek Harness 桌面客户端——本质是「把桌面操作系统变成了 Harness 的可插拔能力层」。

- **不是**：网页套壳（不依赖外置浏览器与外部 HTTP 端口，宿主内嵌、零端口）。
- **是**：与官方同内核（同一 Cordis Host 插件树、同一会话/轨迹/沙箱语义）的桌面应用，
  其桌面特有能力全部通过官方插件机制注入；**主面复用官方 Web UI 发行物**（`dsh-ui://` 内嵌高保真渲染），
  **自绘 Desktop UI 为二期可选**（ADR-006 启用后生效，见 [`13-ui-design.md`](13-ui-design.md)）。

### 目标用户
1. 已将 DSH 作为日常 AI 编程/自动化工具、希望获得原生桌面体验（托盘驻留、快捷键唤出、多窗口）的开发者；
2. **现有 Web UI 的用户**：对浏览器式布局（三栏+tab、深层管理页）不满，期待桌面工作流（键盘优先、命令面板、信息密度）的开发者；
3. 不愿/不便配置 Node 与插件环境的普通用户（一包安装即用）；
4. 需要「后台持续运行 + 会话并行 + 系统级集成」（通知、剪贴板、文件关联）的重度用户。

### 与官方 Web 的关系
- 数据完全兼容：同一 `$DSH_HOME`、同一 profile、同一 session 持久化（JSONL）——Web 与桌面可并存（默认不同时开端口）。
- **主面** = 官方 Web UI 发行物以桌面内嵌形态运行（同质体验 + 托盘/热键/通知等桌面增强）；旧 client 插件随主面原样可用；自绘 UI 启用后另行评估承载（ADR-006/007）。

## 2. 需求矩阵

优先级：**P0** = M1–M3 完成（可天天用）；**P1** = M4–M5；**P2** = M6 及以后。

### 2.1 核心（P0）

| ID | 需求 | 说明 | 判定标准 |
| --- | --- | --- | --- |
| R-01 | 一包安装即用 | 安装后无需 Node/pnpm/额外配置 | 全新 Win10/11 机器安装后直接对话 |
| R-02 | 官方 UI 复用主面 | 主面直接内嵌官方 Web UI 发行物（`dsh-ui://` 加载），不做像素级自绘；键盘优先/状态投影等体验增强通过官方槽位注入 | M1 起可打开官方 UI 并完成日常对话全流程 |
| R-02b | 旧插件兼容 | 用户现有 web client 插件（terminal/rule-manager/restart）不被丢弃 | host 半零改动可用；client 半随官方 UI 主面原样可用 |
| R-03 | 宿主内嵌、零端口 | 默认不监听任何 HTTP 端口 | `netstat` 无 308x 监听；卸载后无残留 |
| R-04 | 同一数据目录 | 与 `dsh web` 共享 profile / sessions / credentials | 切回 Web 会话历史无缝 |
| R-05 | 会话持久与后台 | 关闭窗口不杀宿主（托盘驻留）；任务在后台继续 | 关窗→托盘→agent 继续跑→通知完成 |
| R-06 | 桌面原生通知 | agent 完成/需要审批/出错 → 系统通知（可点开定位会话） | 通知点击聚焦对应会话窗口 |
| R-07 | 全局热键唤醒 | 默认 `Ctrl+Shift+Space` 呼出快速输入（Spotlight 式），可配置 | 任意应用内热键唤起即打字即回车 |
| R-08 | 托盘菜单 | 会话列表、状态、快速问答、退出 | 托盘即用 |

## 3. 非功能需求

| 维度 | 要求 |
| --- | --- |
| 启动速度 | 冷启动到可用 UI ≤ 3s（中端 Win 机器）；宿主热启动（常驻）≤ 300ms 唤起 |
| 内存 | 常驻态 ≤ 400MB（Chromium 多进程开销之上尽量收敛）；空闲会话不活跃窗口自动冻结 |
| 安全 | 默认零端口；renderer 全程 `contextIsolation: true` + 沙箱 + 白名单 IPC（见 08） |
| 隐私 | 使用统计本地化默认关闭；外发仅限官方模型 API 与用户启用的 web 能力 |
| 兼容性 | Win10/11（x64, arm64 可选）优先；macOS/Linux 后置（M5 起） |
| 可审查性 | 每次桌面动作产生结构化日志；敏感操作（剪贴板写、文件删除、外链）过 approval 服务 |
| 版本纪律 | 钉死上游 rc 基线；升级可回滚；文档级 breaking-change 迁移记录（ADR-005） |

## 4. 非目标（明确不做，防范围蔓延）

- **不自研主面 UI**：M1–M3 主面始终为官方 UI 复用形态；自绘 Desktop UI 列为 P2 技术债（ADR-006 启用前不投入）。
- 不做多用户/云同步；不引入账号体系（与官方一致仅本机）。
- 不把桌面做成「插件商店」运营平台；插件装载仍走 `dsh plugin` / patch 机制。
- 不承诺修复上游内核缺陷（如 Windows 子进程闪窗根因在 `dsh-subprocess-local`，见 dsh-terminal 插件边界说明）。

## 5. 成功标准（3 个月可验证）

1. 同一台机器：桌面与 `dsh web` 共享数据，桌面默认零端口。
2. **主面为官方 UI 复用**：M1 起即能在桌面内完成日常对话全流程（托盘/热键/通知齐全），不依赖浏览器与外部 HTTP 端口。
3. 旧插件不丢弃：`dsh-rule-manager`、`dsh-terminal`、`dsh-restart` 的 host 半零改动可用；client 半随官方 UI 主面原样可用。
4. 桌面能力本身可被 `dsh plugin` 列表看到、可被 patch 增删——验证「桌面=插件树」主张。
5. 托盘 + 全局热键 + 通知成为肌肉记忆（R-05~R-08 全部达成）。
